## 1. 需求背景

### 1.1 问题描述

现货管理模块当前以 SPU 维度展示列表，上架状态挂在 SPU 级别。随着 v2.4 "一款多商品" 功能上线，一个 SPU 可对应多个商品、多个 SKC 状态各异，SPU 维度的展示已无法满足运营需求：

- 列表需切换到 SKC 维度，每行展示一条 SKC 及其状态
- 上架状态、推送买手系统状态、测价状态均应在 SKC 维度独立展示
- 编辑/详情页需优先展示 SKC 信息，SPU 信息作为上下文参考

### 1.2 需求清单

| 序号 | 需求描述 | 需求类型 | 优先级 |

| 2 | 上架状态从 SPU 级别下移到 SKC 级别，根据关联商品聚合计算 | 功能优化 | P0 |
| 3 | 列表新增"推送买手系统状态"列（SKC维度）：未推送/已推送/推送失败 | 新增功能 | P1 |

## 3. 修改方案

### 3.1 状态机调整

#### SKC 上架状态（从 SPU 下移）

```
stateDiagram-v2
    [*] --> 未上架
    未上架 --> 已上架: 上架
    已上架 --> 已下架: 下架
    已下架 --> 已上架: 重新上架
```

聚合规则（同款式管理）：全部关联商品下架(13) → 下架；存在未下架 → 已上架。

#### SKC 推送买手系统状态（新增）

```
stateDiagram-v2
    [*] --> 未推送
    未推送 --> 已推送: 推送
    已推送 --> 推送失败: 推送异常
    推送失败 --> 未推送: 重试
```

#### SKC 测价状态（新增）

简单标记字段，无状态机流转：
- `(空)` = 未测价
- `测价通过` = 测价已完成并通过

### 3.2 数据模型调整

**SPU 实体**：移除 `上架状态` 字段。

**SKC 实体**：新增 3 个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| 上架状态 | 枚举 | 未上架/已上架/已下架，根据关联商品聚合计算 |
| 推送买手系统状态 | 枚举 | 未推送/已推送/推送失败 |
| 测价状态 | 枚举 | (空)=未测价 / 测价通过 |

### 3.3 列表页调整

- 展示维度从 SPU 改为 **SKC 维度**（每行一条 SKC）
- SKC编号作为首要显示字段
- 新增行内筛选：推送买手状态、测价状态
- 显示字段新增：推送买手系统状态、测价状态
- 删除 SPU/SKC/颜色 三级视图切换

### 3.4 编辑/详情页调整（SKC优先原则）

| 页面 | 调整 |
|------|------|
| 创建/编辑SPU (Section 7) | 编辑模式顶部新增 SKC 概览区（颜色/尺码/缩略图/修图状态/上架状态/测价状态），SPU 编辑表单在下方 |
| 编辑SKC (Section 10) | 顶部新增 SKC 状态标签区 + SPU 上下文区（只读），SKC 编辑表单在下方 |
| 复色 (Section 11) | 顶部新增源 SKC 信息区 + SPU 上下文区，复色表单在下方 |

### 3.5 实体关系图格式转换

将 ASCII-art 制表符实体关系图转换为 mermaid `erDiagram` 格式，与其他模块保持一致。

---

## 4. 数据迁移

无需数据迁移。新字段均为自动计算/标记字段，存量数据按以下规则处理：

| 字段 | 存量数据处理 |
|------|------------|
| SKC.上架状态 | 根据已有商品关联关系重新聚合计算 |
| SKC.推送买手系统状态 | 默认为空或"未推送" |
| SKC.测价状态 | 默认为空 |
